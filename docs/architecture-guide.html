Deep Dive · 技术细节

魔鬼在细节里:安全、性能与超能力

四块硬功夫支撑起"让 AI 随便写代码也敢直接跑"的底气。

🛡️强制沙箱 + 资源配额

作者脚本永远不在主线程执行,只进 Worker 或opaque-origin iframe。每个场景都有硬上限,防止一段失控代码拖垮页面:

网格数量≤ 1,000
顶点 / 索引≤ 10万 / 30万
纹理≤ 16 张(2048²)
脚本体积 / 执行时间≤ 1 MiB / 3 秒
粒子 / 发射器≤ 2000 / 8 个

⚡GPU 实例化:一次画一千个

一千个相同的无人机不是一个一个画,而是一次 GPU 指令画完(drawElementsInstanced)。同一份几何体只占一份显存,每个实例只存一个变换矩阵和颜色。

Web: EXT_mesh_gpu_instancing
Android: Filament Instancing
iOS: USDZ PointInstancer

🔗安全 URL 与原型污染防护

媒体地址必须走 safeMediaUrl():只允许 https 或干净相对路径,拒绝 ..、反斜杠、协议注入。锚点 ID 拒绝 __proto__ / constructor 等原型污染关键字;多人房间只允许 wss 加密连接。

safeMediaUrl() · isAllowedRoomUrl() · safeAnchorId()

🎨专业渲染管线

WebGL2 PBR 物理材质、5 种色调映射(ACES / AgX / Neutral…)、HDR 泛光、轮廓描边、meshopt 网格压缩解码、材质变体切换、2 骨骼 / FABRIK 反向动力学(IK)——全部塞进 111KB 预算内。

bloom · outline · meshopt · variants · IKSolver

🏷️ 空间特质浏览器 — 给 3D 物体贴一张"行为标签",点击左侧切换

特质(Trait)是本项目最核心的发明之一:不写行为代码,只在物体上声明一个 userData.xr 字段,三端运行时自动实现对应行为。

Philosophy · 设计思路

六个决定,塑造了整个项目

每个架构选择背后都有一个明确的"为什么"。看懂这六条,就看懂了 Three-Live。

🤖

AI 优先,而不是平台优先

大模型擅长写简洁的 Three.js,不擅长写几百行安卓着色器或苹果 AR 样板代码。与其让 AI 学三个平台,不如让平台学 AI 的语言。

落地:标准 Three.js 即输入,编译器负责一切平台差异。
🏷️

声明式:一个标签,一张标签

网页里放一个 <three-live> 就能显示 3D;物体上贴一个 grab: '2-hand' 就能被双手拿起。行为是"声明"出来的,不是"编程"出来的。

落地:Custom Elements + userData.xr 特质 Schema。
🛡️

安全是底线,不是选项

要敢直接运行 AI 生成的代码,就必须假设代码可能出错甚至恶意。沙箱、配额、URL 白名单、看门狗全部默认开启、不可绕过。

落地:Worker/iframe 强制隔离,Boa 双重看门狗,原型污染防护。
🧬

三端一致靠合约,不靠自觉

跨平台项目最大的坑是"网页能拿起来,安卓拿不起来"。字段定义只写一份,三端实现对照同一 Schema,一致性测试强制常绿。

落地:Trait Schema 单一事实源 + Parity Rule + 自动化测试。
⚖️

体积预算:每 KB 都要挣

网页 3D 组件如果动辄几 MB,没人愿意嵌入。项目给每个 bundle 定了 gzip 硬预算(30KB~207KB),构建脚本超标即失败,逼出模块化按需加载。

落地:基础包 + 附加包分层,make web 自动校验预算。
🔄

AI 写完必须能自己验收

AI 看不到浏览器画面,怎么知道写对了?给它一套无 GPU 的命令行工具:静态体检、四视角截图、60Hz 仿真,全部输出结构化 JSON,AI 可以自己看结果、自己改。

落地:three-live-cli validate / render / sim + MCP 服务器。
Verification Loop · AI 验证闭环
